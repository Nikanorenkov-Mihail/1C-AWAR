# Проверка кода 1С (ПроверкаКода)

Прогоняет сгенерированный/отредактированный код BSL через синтаксический
анализатор и сообщает об ошибках структуры.

## Когда использовать

- После генерации или правки любого `.bsl`-модуля — ДО того, как отдать код пользователю.
- Когда пользователь просит «проверь код», «валидируй модуль», «найди синтаксические ошибки».

## Как выполнять

Запусти самодостаточный чекер (Node, без зависимостей):

```bash
node .opencode/skills/1c-code-check/check.mjs <файл.bsl | каталог>
```

- Файл — проверит один модуль.
- Каталог — рекурсивно проверит все `.bsl`.
- Без аргумента — проверит всю выгрузку `20260824/20260824`.

Скрипт печатает ошибки в формате `файл:строка — описание` и возвращает код
выхода 1, если ошибки есть. Если вывод пуст — код структурно корректен.

## Что проверяется

Баланс блоков (открытие ↔ закрытие):
- `Процедура` ↔ `КонецПроцедуры`, `Функция` ↔ `КонецФункции`
- `Если` ↔ `КонецЕсли`
- `Для` / `Пока` ↔ `КонецЦикла`
- `Попытка` ↔ `КонецПопытки`
- `Выбор` ↔ `КонецВыбора`
- `#Область` ↔ `#КонецОбласти`

Строки (`"..."`) и комментарии (`//`) игнорируются — ложных срабатываний на
тексте запросов внутри строк не будет.

## Ограничения

Это структурный чекер, а не полный компилятор: он ловит незакрытые/лишние
блоки, но НЕ проверяет типы, имена методов, синтаксис запросов и
семантику. Для полной диагностики используй `bsl-language-server` (onec-syntax):

```bash
# требуется Java 11+ и jar из https://github.com/1c-syntax/bsl-language-server/releases
java -jar bsl-language-server.jar --analyze --src <каталог> --format json
```

Если такой jar доступен (например, `~/.local/bin/bsl-language-server.jar`),
запускай его вместо `check.mjs`.
